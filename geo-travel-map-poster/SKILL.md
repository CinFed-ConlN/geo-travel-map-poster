# 定位旅行地图海报

把照片位置、地图文字和海报制作连起来完成。用户只要提示词时只交付提示词；要求作图时执行图像编辑。创建、安装本技能本身不触发定位或作图。

本包内置 geo-sleuth 的脚本、数据、地区包和定位参考，不依赖另外安装的 `geo-sleuth` 或 `make-travel-map-poster`。本文件决定坐标优先级、语言和交付范围；定位细节按相关参考执行。

需要核对内置资源版本或许可时读 [upstream-sources.md](references/upstream-sources.md)。

## 1. 先提炼用户要求，再读取照片信息

在定位和写提示词之前，从用户最新消息及已明确的上下文提取：

- 内容底图与风格参考各是哪张；多张照片分别对应的位置。
- 经纬度、坐标来源与坐标系，城市、区域、国家、地标，以及这些信息是拍摄地点还是用户指定的地图目标。
- 地图标注语言、英文变体、双语要求、指定地名写法；提示词语言与回复语言单独记录。
- 保留的主体、地图位置、比例、颜色、标记，以及“不要文字”“仅英文”“只要提示词”“不要上传图片检索”等特殊要求。

用户明确要求优先于默认值，后续明确修改覆盖早先要求。只对影响执行的冲突或缺项提问；已能从输入判断时直接继续。缺少内容底图且要求保留用户照片时，请用户提供底图。

先查看所有输入图片，识别主体、留白、画面中的坐标文字、地名和截图界面。能取得原图文件时，先运行内置 `scripts/exif.py` 读取 GPS、拍摄时间、焦距、朝向等参数；再按需用 `scripts/ocr.py` 辨读画面坐标或地名。不要把风格参考的 GPS 或截图中另一处地点的坐标当成内容底图的拍摄位置。截图或聊天预览不能恢复被剥离的 EXIF。

示例（用本技能根目录的实际绝对路径替换 `SKILL_ROOT`，用实际照片替换 `photo.jpg`）：

```text
uv run SKILL_ROOT/scripts/exif.py photo.jpg
```

## 2. 按坐标情况选择定位路线

| 输入情况 | 行动 |
| --- | --- |
| 用户消息、内容照片画面或原图参数中有可用经纬度 | 采用提供的坐标作为地图目标；核对格式、坐标系及其指向的地区，跳过重新搜索拍摄点 |
| 没有可用经纬度，只给出大致城市、区域或地标线索 | 在该范围内使用内置 geo-sleuth 找到照片对应位置；不要直接把城市中心作为拍摄点 |
| 没有经纬度，也没有地点线索 | 使用内置 geo-sleuth 从照片信息开始寻找对应位置；不要默认改用无地名装饰地图 |

已有坐标：

- 保留坐标来源及原始值；在含义明确时将度分秒等转成十进制度，检查纬度范围 ±90、经度范围 ±180、南北/东西符号及经纬顺序。有效的零值不是“缺少坐标”。
- 默认先用用户明确指定的地图目标坐标，再用画面中明确属于该照片的坐标，再用原图 EXIF GPS。用户明确要求另一处地图目标时，以目标位置作图，不声称它就是拍摄点。
- 多个来源指向明显不同的位置，而用户未说明采用哪一个；两数的经纬顺序无法判断；坐标残缺、超范围或坐标系不明且影响定位时，先就具体冲突提问。不要擅自交换、补全或重新猜点。
- EXIF GPS 按 WGS84 处理；来自高德/腾讯或百度地图的坐标分别核对 GCJ-02 或 BD-09。只在坐标系明确时使用 `scripts/geo.py convert`；不要把不同坐标系的数值直接当成同一点叠加。无来源说明的十进制度可暂按 WGS84 作粗区域核对，精确落点受影响时再确认。
- 可以反向查找地名、附近地标和地图资料，以准备地图内容；这不构成重新推断拍摄位置。仅据用户坐标不能宣称已用街景验证，也不自动显示经纬度在海报上。

需要定位时，读取 [geolocation-workflow.md](references/geolocation-workflow.md)，执行其中相关步骤。将用户城市/区域作为初始搜索约束，将可见线索和候选位置写入候选板；只有真实证据表明范围不符时才说明并调整。遵守用户对在线图片检索的限制，需要时使用 `intake.py --no-rev`。定位的目标是获得足以制作相应范围地图的位置，不额外开展用户未要求的时间推断或完整调查报告。

定位未能确定唯一点时，保留已支持的城市/区域及不确定性；不能编造楼级坐标、用多个候选的中点定位或画一个确定的拍摄点。若区域级地图已经满足用户要求，可以据该区域制作并简短说明；若制作要求精确标记，则先询问最有帮助的缺失信息。

## 3. 决定地图语言并核对名称

读取 [location-and-language.md](references/location-and-language.md) 中的语言规则。优先级：用户明确指定的地图语言或地名写法 → 地点所属地区的当地书写语言 → 无法判断时使用已核验的当地原名。

- 中国大陆默认中文（简体），香港、澳门、台湾按当地惯用写法与字形；美国默认美式英语，英国默认英式英语，意大利默认意大利语。其他地区按位置选当地语言，而非按用户回复语言选地图语言。
- 用户说“地图用英文”，只改变地图标注语言；继续按用户要求的语言沟通。用户要求整张海报用英文、双语或无文字时，按其指定范围执行。
- 城市、道路、河流、地标及需要出现的方向/图例文字采用一致的语言策略；引用的地名必须核对，保留重音符号及专名。不要为了英美拼写差异改写官方名称。
- 先准备一份短的“原名 → 最终标注”清单供制作使用，将准确字符串写入图像提示词。不要从原南昌参考图继承英文地名。

## 4. 取得对应地图并制作海报

以已采用的坐标或已支持的区域查找当地地图资料。优先使用用户地图素材，其次使用可核验的地图来源；核对城市、水系、路网和地标关系，按来源要求署名。地图语言与当地名称以步骤 3 的清单为准，不能只改城市标题而保留另一座城市的路网。

需要准确路网或落点时，引用真实地图底图并核对合成结果；图像生成的地图纹理不能保证道路、距离或坐标精确。没有地图资料且用户需要准确地图时，请求素材。仅做视觉海报时可基于已知地点和已核验名称作风格化地图，简短说明其视觉表达性质，不声称可用于导航。

默认视觉：

- 照片是主角，保留主体外形、位置、透视、细节和自然光线，沿用原照片比例。
- 在天空、水面、墙面等留白处叠加低对比地图：白色细道路、浅色街区、适合底图的淡色水系；用渐变蒙版向照片内淡出，避免硬矩形边与覆盖人脸/主体。
- 地图约占画面 20%–40%、可见强度约 15%–35%，仅为起始设计建议，按留白与明暗调整。
- 可用小型珊瑚红地点圆点和小型精致衬线城市名；只有确定的目标点才放落点标记。已提供的文字/配色偏好覆盖默认设计，无文字要求同时取消所有文字标签。
- 默认不加大标题、广告、日期或外边框。按需加小指北针，不把拍摄朝向当成北向；无可计算的真实比例时不加数字比例尺。
- 去掉截图的状态栏、播放器、手势条和外框。仅在用户要求原参考风格时读 [reference-style.md](references/reference-style.md)，查看 `assets/style-reference.jpg`；它是风格参考，不能代替用户底图，也不能决定本次地点或语言。

将“输入角色 → 保留项 → 已确定位置与地图素材 → 精确标注文字及语言 → 地图融合与比例 → 排除项”整理为制作提示词。使用当前环境的图像生成/编辑工具，并遵守其图像技能说明；如果使用 `image_gen.imagegen`，本地引用用 `referenced_image_paths`，无本地路径的会话图用包含全部目标图的最小 `num_last_images_to_include`，两者不可同时传入。默认海报背景不透明。没有图像工具时交付可复制提示词并说明图片尚未生成。

## 5. 检查与交付

检查主体未变形、地图淡入自然、地图地点及标签一致、语言与用户要求一致、定位圆点有依据、名称可读且重音/字形正确、没有截图界面或无依据的距离。发现错误则修正再交付，不覆盖原图。

用户要成品时展示成品并简短说明地点来源；用户要提示词时只交付提示词与影响使用的实际限制。保留定位证据供核查；只有用户要求定位解释，或需要解释不确定性时，才附定位链和证据图，不默认展开完整定位报告。

## 运行环境

Python 3.10+、`uv`、`curl`；脚本通过 `uv run` 按需取得自身声明的依赖。首次设置或环境报错时运行 `uv run SKILL_ROOT/scripts/doctor.py`。在线服务探测按需加 `--network`。原有定位参考中的 `${CLAUDE_SKILL_DIR}` 在本包内始终指本技能根目录；可直接替换为根目录绝对路径，Windows 可用 PowerShell 环境变量写法。缓存与候选板写到本次任务的可写工作目录，不写入技能包。
